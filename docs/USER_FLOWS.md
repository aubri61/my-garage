# 사용자 흐름

## 공통

`/login` → 세션 로그인 → `/mode` → `/renter` 또는 `/owner`. 상단 메뉴로 모드를 즉시 변경한다. 새로고침은 `/api/users/me`로 복원하며 로컬 저장소 플래그는 권한을 부여하지 않는다. 로그아웃과 401은 사용자 데이터 캐시를 정리한다.

## 차량 빌려주기

`/owner` → `/vehicles/register` → 공유 설정하기 → 공개 픽업 설명·위도·경도와 공유 여부 저장. 기존 차량은 비공개로 시작한다. 공개 중단은 새로운 신청·승인을 차단하지만 기존 승인된 계약을 자동 취소하지 않는다.

신청 카드에서 승인/거절 → 계약 조건 펼치기 → 조건 동의 → 대여 시작 대기 또는 활성. 활성 요청에 대해 잠금 해제 승인/거절. 필요하면 가상 차량 잠금, grant 회수, 대여 종료. 회수는 재발급하지 않으며 대여를 종료하고 새 계약을 진행해야 한다.

각 소유 차량에서 OTA Security Lab을 펼칠 수 있다. 기존 `/garage`에도 소유자 OTA 진입을 유지한다.

## 차량 빌리기

`/renter` → 차종/픽업 설명 검색 → 지도 또는 목록으로 선택 → 기기 현지 날짜·시간 입력 → 신청. 서버에는 UTC ISO-8601로 전송한다. 지도 키가 없어도 목록과 폼은 사용 가능하다.

내 대여 요청에서 승인/거절 확인 → 계약 조건 펼치기 → 동의 → 서버 grant 활성 확인 → 잠금 해제 요청 → 소유자 승인 후 `UNLOCKED` 확인. 새로고침으로 DB 상태를 복원한다. PKI 필수 모드에서는 인증서 서명 폼을 이용한다.

## 오류 및 복원

- 예약 충돌은 409와 `RENTAL_CONFLICT`를 표시한다. 자동 재시도하지 않는다.
- 다른 차량을 선택하면 폼을 새로 마운트하여 이전 성공/오류를 격리한다.
- 인증 만료는 401 후 로그인 필요 화면으로 전환한다. CSRF 오류는 다음 수동 요청에서 새 토큰을 가져온다.
- SSE는 연결 상태를 표시하며 연결 실패 시 REST 주기 조회를 유지한다. 재연결의 `ready` 이벤트는 모든 관련 Query를 다시 조회한다.
- 시작/종료·회수 상태는 프론트 시계로 확정하지 않는다. 서버가 재조회/제어 시 확정한다.
