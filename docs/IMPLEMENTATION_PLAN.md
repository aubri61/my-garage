# 구현 상태 및 후속 계획

구체적인 최종 테스트 결과와 미검증 항목은 VALIDATION.md에서 관리한다. 실제 운영 서비스 완료로 해석하지 않는다.

## 남은 기능 / 알려진 한계

- **지도:** 사용자 설정 키로 `localhost:3000`의 실제 Kakao SDK/타일/마커를 검증했다. 데모·대여자 목록·차량 등록·소유자 픽업 설정이 공통 지도 컴포넌트를 사용한다. Kakao Services 주소/장소 검색, 450ms debounce, 최대20개 결과, 지도 클릭/마커 드래그 후 역지오코딩을 지원한다. 테스트 도메인은 별도 등록이 필요하다. 다른 hostname/port는 Kakao 웹 도메인 등록이 필요하다.
- **기간별 탐색:** 공유 목록의 차종/위치 검색과 요청 시 충돌 검사는 구현했다. 기간별 서버 가능 여부 조회와 공개 상세 접근 제한을 추가했다. 페이지네이션·예약 가능 달력·외부 차종 카탈로그 연동은 없다.
- **PKI 운영:** CA는 로컬 수동 fixture, 단일 leaf → CA, CRL/OCSP·기기 등록/키 회전·KMS는 없다. 전용 하드웨어 키 보호와 브라우저 지속 키 보관은 구현하지 않는다.
- **상태 전이:** 서버 조회/제어가 시간 전이를 확정한다. 백그라운드 expiry scheduler와 알림 전용 영속 이벤트 큐는 없다. 만료 여부는 모든 제어에서 현재 시각으로 검사한다.
- **운영 규모:** 단일 서버의 in-memory SSE만 지원한다. 다중 서버 pub/sub, 영속 알림/읽음 상태, 이벤트 재생, 응답 페이지네이션, 캐시 부하와 대규모 동시성 벤치마크는 후속 대상이다.
- **감사:** 성공한 전이만 DB 기록한다. 거부 이벤트의 별도 트랜잭션 감사와 사용자 조회 UI/API는 없다.
- **취소:** CANCELLED 상태는 예약되어 있지만 대여 취소 API/UI는 없다. 신청 거절 및 계약 이후 소유자 종료를 제공한다.
- **UI 보존:** `/garage`와 `/demo/garage`에 이전 차량 관리/목업 체험 코드를 유지했다. `/demo`는 새 공유 흐름의 독립 체험으로 교체했다. 공유 서비스의 실제 진입은 `/mode`, `/owner`, `/renter`다. 목업 충전/인증서 체험은 실제 공유/PKI가 아니다.
- **DB 관리:** 기존 ddl-auto=update의 additive 확장을 사용했다. 운영용 버전 마이그레이션 도구와 데이터 보존 마이그레이션 배포 절차는 후속 범위다.
- **실서비스 제외:** 실제 차량 제어·GPS·결제·전자계약 서비스·보험·면허/실소유권 검증을 하지 않는다.

## 다음 우선순위

1. 운영 도메인을 Kakao에 등록하고 주소 검색/역지오코딩이 필요하면 추가.
2. 서버 검색·페이지네이션·예약 달력과 사용자 목록 UX 개선.
3. 별도 거부 감사, 알림 보관/조회, 상태 scheduler 필요성을 실제 운영 요구에 맞춰 결정.
4. 다중 인스턴스 SSE, DB query/잠금 부하 검증 및 버전 마이그레이션 도입.
5. 운영 신원 검증/인증서 수명 관리가 필요한 경우 fixture와 분리된 설계를 추가.

Git commit, push, merge, 배포 및 기존 데이터 초기화는 수행하지 않았다. 실제 e2e는 고유 테스트 계정/차량/계약 데이터를 DB에 생성한다. 테스트용 CA/기기 키는 Git 제외 `.local` 또는 임시 폴더에서만 사용한다.

## 2026-10-09 실제 데이터 연동 보강

실제 등록 폼에 종속 차종/연식 선택과 픽업/공유 설정을 추가하고, 기존 요청과 호환되는 한 트랜잭션 저장을 구현했다. 소유자 차량 이벤트와 개인정보 없는 공개 목록 이벤트를 추가했으며 기간별 예약 가능 조회, 공개 상세 DTO, 계약 동의 표시와 알림/초기 조회 경합 복구를 보완했다. 실제 브라우저 A/B/C 및 PostgreSQL 직접 조회 결과는 [실제 데이터 연동 보고서](LIVE_DATA_INTEGRATION.md)와 [검증 기록](VALIDATION.md)에 기록한다.

## 2026-10-09 Lovable 전체 UI 이식

공통 원본 디자인 토큰/헤더/인증, 대여 marketplace, 소유자 통계·차량 수정, 4구획 등록 폼, 예약/계약/모의 서명/디지털 키/보안 페이지를 구현했다. 서버 가격 견적 및 계약 가격 스냅샷을 nullable 컬럼으로 추가했고 기존 행 가격은 채우지 않았다. 테스트는 개발 DB 대신 mygarage_e2e 제한 계정과 전용 백엔드에서만 실행한다. 사용자 미확인 이미지 4장은 사용하지 않았다.

상세 파일과 API·검증·사진 준비 방법은 [Lovable 통합 보고서](LOVABLE_INTEGRATION.md)에 기록한다. 후속 작업은 테스트 도메인의 실제 Kakao 성공 검증, 사진 사용 권한 확보/등록, 운영 마이그레이션 도구, 법적 계약/결제 및 운영 PKI 등이다. 대여자 직접 재잠금 권한은 새로 열지 않고 소유자 전용 잠금을 유지했다.

## 2026-10-09 디자인 통합 집중 작업

이번 요청에서는 신규 기능 개발을 중단했다. 시작 시점부터 존재한 백엔드/가격/계약/차량 수정 변경은 보존했으며, 이번 작업은 기존 프론트 컴포넌트와 스타일에 한정했다. 신규 DB 스키마, 가격·결제·서명 저장, API 변경은 추가하지 않았다.

### 적용 범위

- **1. 차량 탐색**: `reference/design-reference/src/routes/index.tsx`와 `styles.css`의 Lovable 토큰 및 필터(300px) / 지도 / 두 열 차량 카드 구성을 사용했다. 제조사 pill, 전기차 필터의 강조 영역, 카드 이미지 비율, 버튼·요금 계층을 정리했다. 기존 실제 조회/기간·가격·차종 필터/정렬/Kakao 지도 선택/서버 견적·신청/SSE를 유지했다.
- **2. 소유자 대시보드**: Stitch `_2/code.html`, `screen.png`의 요약 카드와 차량 관리 구성을 기존 Query/렌탈 컴포넌트에 적용했다. 실제 차량 수/공유 차량/승인 대기/확정 및 이용 중 계약을 표시한다. 수익·평점 등 미지원 데이터를 만들지 않았다. 실제 차량 관리·소유자 승인·권한 회수·잠금·보안 화면 진입을 유지했다. 새 요청이 없고 계약만 있는 경우에도 요청 빈 상태를 표시한다.
- **3. 차량 등록**: Stitch `_3`의 구획별 카드/번호 표시/우측 미리보기 구조를 이식했다. 상단 링크는 해당 입력 구획으로 이동하며 진행 완료를 가장하지 않는다. 미리보기는 입력 중인 값만 사용하고 저장은 기존 API로 수행한다. 종속 카탈로그/번호판 검증/픽업 검색·지도·좌표/공유 설정/오류·성공 상태를 유지한다. 현재 존재하던 요금 입력은 보존하되 가격 저장 기능을 추가하지 않았다. 사진 업로드나 임시 저장 버튼을 만들지 않았다.
- **4~5. 부분 적용**: 계약, 로그인/회원가입, 예약/디지털 키/보안/모드/차량 수정에 공통 입력·버튼·상태·카드 스타일을 적용했다. 계약 동의와 PKI 동작은 기존 컴포넌트를 유지했다. 계약 전용 문서·서명 2열 레이아웃(Stitch `_4`), 로그인 전용 레이아웃(`_1`), 차량 상세(`_6`) 전체 이식은 미완료다. 기존 상세 확인 및 `/garage` 기능은 유지했고 신규 차량 상세 라우트를 만들지 않았다.

### 디자인 소스와 기능 경계

Lovable 토큰을 가장 우선하고 Stitch `connected_mobility_marketplace/DESIGN.md` 및 화면 HTML/스크린샷은 페이지 구성 기준으로 사용했다. 기존 `.sharing-app`의 로컬 색상 토큰이 Lovable root 토큰을 덮어쓰던 문제를 제거했다. 라우터/상태관리 교체, 가상 REST 응답, localStorage 로그인, 그림 지도, 버튼 애니메이션 기반 성공 처리 등은 추가하지 않았다. 기존 차종 참고 이미지/placeholder를 유지했다.

### 검증

- TypeScript, 프론트 단위 8건 통과.
- `NEXT_FORCE_WORKER_THREADS=1 npm run build` 통과. 기본 빌드는 Turbopack의 로컬 worker 포트 권한 제한으로 실패했으며 저장소의 기존 worker-thread 옵션으로 성공했다.
- 백엔드 `./gradlew test --rerun-tasks`: 57건, 실패/오류/제외 0. 인증·CSRF·소유권·동시성·SSE·계약·PKI·OTA 포함. 기존 격리 `mygarage_e2e` DB/역할을 사용했다.
- Playwright 실제 공유/API+UI 회귀: 결과는 아래 최종 확인 항목에 기록한다. 기존 6개 숨긴 데모 등록 시나리오와 별도 브라우저 PKI 시나리오 1건은 제외된다. 브라우저 PKI는 이번 실행에서 재검증하지 않았으며 백엔드 PKI 테스트는 통과했다.
- 실제 SDK의 Kakao 연결 실패 안내와 재시도 UI는 확인했다. 지도 성공/실제 장소 검색 성공은 검증하지 못했다. 기존 SDK fixture 테스트 성공과 실제 연결 성공을 구분한다.
- 브라우저 캡처는 새 격리 계정/차량/계약을 실제 API로 생성해서 수행했다. 캡처 중단 실행의 잔여 데이터는 격리 DB에 보존했고 기존 테스트 행을 정리하지 않았다. 정상 종료 실행 및 회귀 테스트는 해당 실행에서 만든 namespace만 정리했다.
- 개발 데이터 삭제/DB 초기화/Git commit/push/배포는 수행하지 않았다.

검증 로그: `/private/tmp/my-garage-design-{backend-tests,e2e,build,lint,render}.log`. 화면 캡처: `/private/tmp/my-garage-design-{renter,owner,register,contract,edit,security,key,bookings,mode}-{1440,768,390}.png`, 로그인/회원가입 1440·390px. 최초 캡처에서 인증 준비 화면이 섞인 것을 발견해 최종 캡처는 준비된 헤더/콘텐츠 이후에 수행했다.

### 최종 확인 결과

- 최종 코드 Playwright 19건 통과, 7건 제외. 실제 API 등록 → 양측 계약 동의 → SSE → 소유자 잠금 해제 승인/재잠금 → OTA를 포함한다.
